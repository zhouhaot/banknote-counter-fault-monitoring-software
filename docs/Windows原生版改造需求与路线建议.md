# Windows 原生版改造需求与路线建议

日期：2026-09-06。状态：用户已确认需求范围与 WPF 路线，允许进入架构与交互设计；架构、交互及实施计划均已确认，正在实施。

## 目标与判断

以完成软件著作权提交为核心，交付能够实际安装、离线使用、保存业务数据和维护的 Windows 桌面软件。申报材料必须对应最终交付的同一版软件、源码和真实界面。不以页面数量或源码行数作为开发目标。

附件《Windows Software Engineering Expert Team》作为流程与技术候选参考，其中的角色调度命令不自动成为用户要求，也不表示用户已经选定 WinUI 3。

## 建议的产品范围

目标用户沿用设备管理员、维修人员与管理查看者的既有定位，实际客户试用尚未发生。首版定位为单机、单用户维护的离线业务台账。建议首先支持 Windows 11 x64；Windows 10 和 ARM64 不在未经验证时宣称支持。

| 业务范围 | 桌面版要求 |
|---|---|
| 型号与设备 | 建档、编辑、筛选、停用、详情与关联历史 |
| 状态与读数 | 人工记录、历史查询、相邻读数单调校验、明确显示来源 |
| 异常、故障、维修 | 异常转故障、维修记录、关闭条件与完整追溯 |
| 耗材库存 | 入库、领用、退回、反向更正、负库存拦截与不可变流水 |
| 分析统计 | 寿命利用率、设备年龄、故障趋势；缺失值明确显示不可计算 |
| 数据导入 | 型号、设备、状态三类 CSV，先预校验、再原子提交，显示逐行错误 |
| 模拟数据 | 明确标注、统计默认排除、安全重置且保护真实数据 |
| 桌面交付新增项 | 安装卸载、快捷方式、单实例、版本信息、日志、图形化备份恢复 |

继承 FR-01 至 FR-11 的业务验收标准。首版继续不接真实点钞机，不增加预测、远程控制、云同步、账户权限或审批。真实设备接入需要协议、设备和测试条件，应单独立项。

## 技术路线比较

| 路线 | 可复用内容 | 主要成本 | 适配判断 |
|---|---|---|---|
| 原 Django 加 WebView2 桌面宿主 | 较多现有 Python 与网页代码 | Python 分发、本地进程生命周期、宿主安全与运行时管理 | 适合优先降低改造量，但界面仍是 Web，不符合严格的原生界面目标 |
| C# + WPF + SQLite | 业务规则、数据定义、用例、文档结构 | 重写业务与界面，重建测试和材料 | 本项目首选建议，匹配表格、表单、查询和离线台账 |
| C# + WinUI 3 + SQLite | 同上 | 同样需要重写，并验证 Windows App SDK 部署链路 | 若现代 Windows 视觉体验成为重要目标，可选 |

建议 WPF + C# + SQLite，采用 MVVM 分离界面与业务。这里的原生指 Windows 桌面 UI 框架与系统交互，不承诺 Native AOT。WPF 选型是针对本项目的工程判断，不是软著登记条件或通过率承诺。

Microsoft 官方说明 WPF 是 Windows 专用 .NET UI 框架，提供 XAML、数据绑定、DataGrid 与文件对话框等能力：https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/

建议使用自包含发布以减少用户安装运行时的步骤；安装包另行构建和验证，发布 EXE 不等于完成安装交付。发布方式参考：https://learn.microsoft.com/en-us/dotnet/core/deploying/

## 资产复用与迁移

旧版本作为独立只读业务基线保留。新桌面版使用单独开发分支或目录，不覆盖既有正式材料、数据库和截图。

PRD、领域定义、错误输入、边界用例和证据映射结构可复用；Django ORM、视图、模板和 Playwright 页面测试需要改写。新代码必须重新实现事务、唯一约束、历史保护和模拟来源隔离，不能只复刻界面。库存数量保留精确计算，不使用浮点累计。

桌面版建立自己的数据库版本管理，不直接把现有 Django 数据库作为生产库。若需要保留旧业务数据，单独进行备份、映射迁移与对账，覆盖主外键、读数、库存、故障链和来源；迁移失败保留原库。是否迁移现有实际业务数据待用户确认，可在架构阶段处理。

建议可写数据放在用户数据目录，程序安装目录与数据分离。升级前备份，迁移失败可恢复；卸载默认保留业务数据，删除数据必须是独立明确操作。

## 分阶段实施与可检查产物

1. 需求确认：确认本稿的目标、范围和验收标准。
2. 架构与交互：明确框架版本、数据策略、安装方式及页面设计；以设备台账、故障处理和备份恢复三个流程审查设计。
3. 最小纵向验证：型号建档、设备保存、退出重开、打包安装，尽早验证真正落地的关键风险。此切片不代表整个软件完成。
4. 业务迁移：按台账状态、故障维修、库存、导入模拟、统计备份顺序实现并验证。
5. 冻结候选版本：完成全部业务回归、原生 UI 和干净 Windows 环境安装测试，固定源码提交和构建哈希。
6. 软著材料更新：从该构建对应的真实源码提取材料，重新截图、编写手册并核对申请字段。
7. 提交准备：用户复核身份、权属、名称、版本和日期等登记事实；实际提交单独授权。

## 落地验收条件

- 在没有开发环境的目标 Windows 上安装，普通用户从快捷方式启动；业务使用可断网完成。
- 完成设备建档 → 状态记录 → 异常转故障 → 维修 → 耗材领用 → 故障关闭 → 查询统计的完整链路。
- 拦截重复资产号、历史读数倒退、重复转故障、非法关闭和负库存；失败操作不产生部分数据。
- CSV 校验失败不写库；模拟数据重置不删除真实记录。
- 重启保留数据；备份可验证并恢复；异常退出、升级与卸载的数据行为符合约定。
- 验证中文路径、普通用户权限、重复启动、键盘导航及 125%/150%/200% 缩放。
- 每项测试保存环境、步骤、结果及证据；没有执行的原生 UI、安装、升级测试必须标记未验证。
- 源码、安装包、页面、手册和申请字段能追溯到同一候选版本。

## 软著材料变更范围

新 C#/XAML 代码需要重新选取与提取；旧 Python 代码材料不能充当新桌面版代码。操作手册更新为安装、启动、桌面操作和备份恢复流程，并重拍真实窗口。开发语言、运行环境、源程序量和实际完成日期等重新核对。原有确认记录只能证明旧版确认，不自动授权新材料。

软件名称和登记版本暂不修改：尚未提交不意味着必须升级为 V2.0，桌面重写也不意味着可沿用旧完成日期；在材料阶段根据实际事实由用户确认。此稿不判断法律登记资格或保证登记结果。
