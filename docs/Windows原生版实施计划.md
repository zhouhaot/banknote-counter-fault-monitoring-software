# Windows 原生版实施计划

日期：2026-09-06。状态：用户已确认，正在连续实施。依据已确认的桌面需求、架构与交互稿。任务验收结果见《Windows原生版实施进度.md》，本文保留实施与退出条件。

## 目标和执行约定

交付 Windows 11 x64 的真实 WPF 软件、可验证安装包，以及同一版本对应的软著材料。先打通“安装→建档→保存→重启”的实际使用路径，再扩展全部 FR-01 至 FR-11。

计划确认后按任务连续执行；依赖安装、常规修复、测试、代码审查与已授权 GitHub 正常推送不逐项重问。只在影响已确认范围的变更、需要用户认证、真实数据迁移、采购或正式材料人工门禁时请求必要输入。阶段状态始终区分代码、构建、测试、原生运行、安装和材料审核。

## 工作区和发布边界

1. 核实主工作区及 implementation-v1 工作区状态，记录旧实现提交和当前设计文件哈希；只读使用旧版作业务参照，不修改其数据库、源码或正式材料。
2. 建立隔离的 codex/windows-native 实施工作区，转入已确认设计和计划，避免 master 中旧项目进度被误认为桌面实现。
3. 推送前检查分支全部可达历史，而不只是当前文件。旧分支可能包含正式软著身份字段，不能因当前树已删除这些文件就直接推送继承历史。
4. 若历史含超出授权的个人资料，保留本地原仓库，另建仅含新桌面源码与脱敏工程文档的干净发布仓库/历史，不重写或强推原仓库历史。保持实现提交与发布提交映射及文件哈希。GitHub 空仓库也不能作为忽略历史审查的理由。
5. 仅上传新源码、必要设计、构建/测试脚本、依赖锁定、安装器脚本及脱敏测试摘要。身份材料、真实运行库、日志、秘密和本机路径清单不上传。安装 EXE 是否作为 Release 资产发布另行处理，不把大文件直接提交 Git。
6. 远程为已配置 origin；可用命令级空代理绕过失效本机代理，不修改全局代理。不强制推送，远程发生变化先检查。读取权限已验证，写权限在首次正常推送验证，认证失败不宣称上传成功。

第3—4项是对已确认分支隔离方案的发布补充：保持本地完整业务参照，同时防止代码授权被扩大为历史身份材料上传。

## T0：工具链与验证路径

依赖：无。范围：desktop/global.json、依赖锁文件、scripts/、测试与安装环境记录。

- 核实 Windows 系统、架构、磁盘空间、.NET SDK、NuGet 和安装器。安装 .NET 10 SDK并锁定稳定补丁，保留旧SDK供现有项目使用。
- 核验 WPF、SQLite、MVVM、CSV依赖真实版本与许可证，建立锁文件。恢复失败先定位网络/证书/版本原因，不反复改依赖猜测。
- 验证原生 UI Automation 测试能力；本会话 CUA 原生桌面操作不可用，需要通过独立 Windows 测试工具实现并真实运行。工具不可用需记录，不把编译当UI测试。
- 确定干净 Windows VM/测试机路径。若无法自动建立，继续独立开发和本机验证，但安装验收标记阻塞，交付前请求用户提供必要运行条件。

退出条件：工具链检查有结果，构建/测试命令与支持环境写明；缺项有精确错误及影响范围。不能因此宣称业务功能完成。

## T1：工程骨架与存储基础

依赖：T0。文件：Desktop启动与窗口、Core契约/错误、Infrastructure连接/迁移/调度、UnitTests和IntegrationTests。

- 建立三个工程、解决方案和测试工程。统一配置、错误映射、日志、用户数据路径及单实例入口。
- 写存储契约失败测试后实现迁移记录、事务、来源约束、操作回执、写队列、查询结果版本控制与维护门控。
- 单元测试覆盖数值溢出、错误映射；真实临时SQLite覆盖迁移幂等、外键、无效来源组合、失败回滚和重复OperationId。
- 明确首次建库与已有库损坏的区别；不能自动覆盖坏库。连接只在所属线程使用，数据库工作不阻塞UI。

退出条件：Release构建、基础测试通过，原生窗口实际启动，错误日志可追溯。尚不满足完整软件验收。

## T2：型号设备纵向切片及早期安装

依赖：T1。文件：Registry业务实现、型号/设备View与ViewModel、对应测试、packaging/。

- 实现FR-01/02的型号建档、设备建档、编辑、查询和停用。表格只读，编辑使用表单。
- 先写重复型号、重复资产编号、无效引用、乐观并发冲突和历史引用保护测试，再实现。
- 实现查询分页、保存反馈、取消未保存修改；原生UI验证新增型号→新增设备→退出→重开→查询。
- 生成自包含目录和用户级安装包雏形，测试快捷方式、中文路径、普通用户运行及卸载保留数据。不能因安装器成功构建就写安装通过。

退出条件：上述业务、真实UI和安装证据齐备；若干净机验证暂缺，只能标记本机运行通过。此时尽早解决打包问题，避免全部业务完成后发现不能分发。

Git节点：审查新增代码、依赖及可达历史后，首次向GitHub正常推送桌面开发分支，验证写权限。

## T3：状态与异常

依赖：T2。文件：Operations服务、状态与异常页面/测试。

- 实现FR-03/04，五种状态、记录时间与来源展示、读数增量、异常登记和关闭。
- 测试同时间重复、历史插入低于前值/高于后值、Int64边界、不同来源父子引用、失败不写入和重复命令。
- UI显示“最近人工记录状态”，无记录不显示在线或实时。错误保留表单并给出冲突记录。

退出条件：规则、真实库和原生页面链路通过；更新FR证据映射。

## T4：故障与维修闭环

依赖：T3。文件：Maintenance服务、故障/维修页面及测试。

- 实现FR-05/06及异常转故障，保留设备和异常回链。
- 测试重复转换、转换事务失败、无维修关闭、无最终结果关闭、时间倒序、关闭后新增/改删维修被拒绝。
- UI验证异常→故障→开始处理→维修→关闭→重新查看只读历史。非法按钮禁用只是提示，服务层仍检查。

退出条件：完整闭环和非法路径通过，记录可追溯。

## T5：库存与耗材

依赖：T4。文件：Inventory服务、SQL约束/触发器、库存流水页面及测试。

- 实现FR-07入库、领用、退回、调整和反向更正。数量最小整数单位存储，累计checked。
- 测试小数精度、零/负/超大数量、负库存、重复提交、不同设备故障关联、重复反向更正、直接SQL更新删除被拦截。
- 维修记录与领用为独立事务；测试领用失败时已保存维修仍可查看，不能误报两者共同提交。

退出条件：真实库流水汇总与显示库存一致，关键并发/幂等测试和原生领用流程通过。

## T6：导入与模拟来源

依赖：T5。文件：Imports、Simulation服务/页面/测试。

- 实现FR-10/11，三类CSV与现有表头保持一致，5 MiB/10000行/2000字符限额。
- 测试引号换行、编码、缺表头、越界、重复行、引用不存在、预览后内容变化、预览后数据变化、提交取消及事务中断；失败不产生部分业务记录。
- 模拟集覆盖已有业务链，创建/重置都受来源约束；测试重置不会删除人工或CSV数据，错误跨集引用拒绝。
- 导出错误清单不得把公式内容直接变成可执行单元格。

退出条件：真实UI导入成功与逐行错误路径、模拟创建和重置均通过。

## T7：统计与桌面体验

依赖：T6。文件：Analytics、概览/分析页、UI样式及测试。

- 实现FR-08/09寿命利用率、年龄和故障趋势；缺额定寿命/读数/启用日期均不补造零值。
- 单元与集成测试验证公式、日期边界、筛选、模拟默认排除及图表和数据表一致。
- 加载500台设备/10万记录/1万行导入规模，记录硬件、冷启动、分页P95和长任务响应；目标按已确认架构，失败先定位查询/线程瓶颈。
- 检查最小窗口、125%/150%/200%DPI、键盘焦点、高对比度、查询过期响应、未保存退出、多屏可见位置。

退出条件：性能与交互结果真实记录；未达目标列为问题，不改口径掩盖。

## T8：备份恢复与升级保护

依赖：T7（底层维护门控在T1建立）。文件：Backup服务、维护恢复状态机、文件测试、备份页面。

- 实现一致快照、manifest、校验、回退快照、阶段日志和受控替换。
- 测试损坏备份、哈希不符、过新schema、外键错误、权限不足、空间不足、连接未关闭、迁移失败。
- 对替换前、替换中、重开前等故障点注入异常并重启，确认原库或回退库可恢复，旧WAL不混入新库。
- 测试升级保留数据、失败回滚和卸载保留数据；用户级程序目录与数据目录分离。

退出条件：恢复成功、失败及中断路径都有证据；备份存在不等于恢复验证通过。

## T9：候选版冻结与发布验证

依赖：T0—T8。文件：发布清单、依赖声明、测试报告、证据映射、安装器。

- 对全部FR执行回归；同一候选源码完成代码/安全审查，修改后复测受影响路径。
- Release构建、依赖漏洞审计、锁定还原、安装包生成；保存提交、构建版本、文件hash、运行依赖及签名状态。
- 干净Windows上实际安装并执行完整业务链、升级和卸载，记录系统和架构。测试副本用隔离演示数据。
- 推送已审查代码和脱敏报告，不上传身份资料或真实数据库。GitHub正常推送已授权，无需再次请求；失败报告明确原因。

退出条件：阻断缺陷清零且真实安装/运行验证完成，才可进入正式材料生成流程。当前未取得签名不宣称已签名或无系统提示。

## T10：软著材料及提交准备

依赖：T9。使用 software-copyright-materials 技能，单独原生版材料目录，避免覆盖旧材料。

- 从最终源码重新建立业务理解、字段、代码候选和提取清单；源程序量按实际计算，名称/版本/完成日期按事实确认。
- 从冻结原生构建拍摄真实截图，按实际页面编写操作手册，覆盖安装、启动、业务、备份和异常处理。
- 保留技能要求的业务、申请字段、代码选择、截图方式、Markdown人工门禁，旧确认不能自动代替新材料确认。
- 正式文件经真实性、版式和跨材料一致性检查后建立提交包；身份字段由用户补齐。实际官方提交须单独授权。

退出条件：明确区分软件验收、材料验收、身份字段复核与实际提交状态，不承诺登记结果。

## 每个切片的验证与交接

新业务规则按失败测试→最小实现→通过测试→代码审查推进。每个实现切片记录Task、变更文件、规则、测试命令/结果、已知问题与下一依赖。不为文案等低风险变更制造镜像测试。代码提交前运行适用构建/测试、依赖审计和diff检查；包漏洞工具实际命令在T0验证后固化，不照搬尚未验证的CLI参数。

证据索引包含FR号、用例、源码/构建hash、环境、步骤、结果和截图。每个切片通过才推进依赖项，独立工作可继续；不把缺少干净测试机或UI工具隐瞒为全部通过。
